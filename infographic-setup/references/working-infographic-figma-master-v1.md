## Component inventory

Use semantic layer names; do not flatten the page before its content and review are approved.

| Component / layer role | Purpose | Must vary with the argument? |
|---|---|---|
| `Promise` | oversized work moment or outcome | yes |
| `Semantic anchor` | tag, tab, stamp, route marker, selected phrase | yes |
| `Context` | short instruction that tells the reader how to enter | yes |
| `Spatial structure` | map, path, table, matrix, spectrum, stack, timeline, comparison | yes, it is the visual claim |
| `Macro region` | meaningful section of the argument | yes |
| `Micro unit` | condition, variable, example, exception, owner, or label | yes |
| `Connector / axis` | honest relation, reading direction, shared scale, or hand-off | only when it communicates one |
| `Outcome / next move` | a real changed action | yes |
| `Boundary / source` | scope, assumption, source, exception, or ownership limit | yes |
| `Motion state` | named component state for reveal, regrouping, comparison, or trace | only when motion teaches something |

## Design tokens are roles, not a theme

- **Ground:** quiet, high-lightness field that keeps dense information readable.
- **Ink:** strong dark type and connection logic.
- **Lead colour:** the reader's entry / current condition.
- **Support colours:** two to four categories, states, routes, or outcome classes.
- **Exception colour:** a bounded issue, customer risk, warning, or boundary—not automatic danger
  theatre.
- **Surface:** thin dark outline, controlled corner logic, low diffuse shadow only where grouping
  or object hierarchy needs it.

The same hex values, pastel palette, handwriting, cards, or composition must never become a silent
brand requirement. Use a colour only if the reader can say what difference it encodes.

## Static and motion rules

The static frame must independently satisfy the 3-second promise, 10-second orientation, and
30–90-second deep-use test. If animated, use `motion-engine-v2-semantic-states.md`; each animated
beat must change a named Figma component and the final state must equal the reviewed static export.

## Prototype evaluation

Supplier Date V2/V3/V4 are retained as rejected comparisons: respectively a process-card sequence,
a sparse route, and an independent-column worksheet. The selected V5 is a coherent working object:
customer need-by governs how one supplier date-change ticket is assessed before credible exposure
and recovery tests, while the current customer date stays visibly held until one joint-exception
condition is met.

It remains a design test, not an adopted universal template: its promise-control-card form must be
rejected whenever the next opportunity is really a comparison, taxonomy, map, data display,
spectrum, or different spatial claim.
