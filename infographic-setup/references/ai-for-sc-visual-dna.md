## The Core Principle

The image is a designed document, not a designed graphic. Every element on the canvas carries real content. The visual system serves the data — not the other way around. The viewer should be able to screenshot and use the image without reading the caption.

What changed from v2.0: the 4-structure limit is removed. Each post now has a format matched to its specific use case from the 50-format library. The VISUAL ANCHOR block gives the chosen format its spatial identity. The tool identity system is unchanged — it remains the colour and brand layer.

## Tool Identity System (The Defining Rule)

Every AI for Supply Chain post takes on the complete visual identity of the tool it features. The image looks like it belongs to that tool — not to Shetty's Desk. The tool's palette and symbolic form are the image's brand.

**Critical rule on tool symbols**: Gemini cannot reproduce copyrighted logos. Do NOT ask it to "include the Claude logo" or "include the ChatGPT logo" — this produces generic placeholders. Instead, describe the geometric form of the symbol precisely. Gemini renders described shapes accurately. The colour + geometric form together produce instant brand recognition without copying a trademark.

## The Hero Number

Every post has one number that is the reason to save the image. It is 3–4× larger than all surrounding text. It is real and specific — never an estimate, never "X%".

**For AI for SC posts, the hero number is the time comparison:**
- Format: "[Manual time] → [AI-assisted time]"
- Example: "3 days → 20 min" for an RFQ post
- Source: Field benchmarks — industry-reported task durations for manual vs. AI-assisted work
- Placement: Prominent near the top or as the opening element of the first content zone

**Finding a credible benchmark**: If the post covers a real SC task (RFQ writing, safety stock calculation, supplier scorecard), there is always a documented industry benchmark for manual time. Use it. If it cannot be sourced, frame conservatively ("typically") — but never invent a specific figure.

## Typography Rules

| Element | Style |
|---|---|
| Post heading | Bold, large, 5–8 words maximum. One word or phrase in accent colour (not the whole heading). |
| Section / card labels | ALL CAPS or Title Case Bold. 2–4 words. White on dark or accent-colour on white. |
| Body text per card | Regular weight. 15–25 words maximum. Never a full paragraph. |
| Hero number | Bold, 3–4× larger than body. In accent colour or white. Stands alone — not inside a sentence. |
| Annotation line (optional) | Italic or smaller regular weight. One sentence. Set apart from the grid. Only when the opinion IS the point. |
| Sign-off | Small, bottom of image. "Shetty's Desk · Poornajith Shetty" |

**Maximum 2 font families.** Bold sans-serif for headings and numbers. Regular weight of same family for body. No mixing serif and sans-serif.

---

## Content Density Rules

Total text on image (all labels, all cards, heading, annotation): **80–120 words**.

Per card: maximum 25 words of body text. Card label does not count toward word budget.

**Every number on the image must be real.** If you cannot source a real number, do not put a number there. Remove the data point rather than invent it.

---

## The Annotation Line

**Only used when**: The post's core value is a perspective or reframe — not just information.

**Format**: One sentence. Below the main grid. Smaller than body text. Not bold. Not in a panel — floating, set apart.

**What it is**: Tiger's one-sentence editorial position on the topic. The thing that could not fit in a table.

Examples of the right register:
- "AI writes the document. You own the decision."
- "The gap isn't the tool. It's the 20 minutes nobody builds into the process."
- "Data doesn't make the call. You do."

## The 50 Visual Format Library

Each post uses one format from this library. Format selection is based on what the content IS — the use case type, the output type, and the insight structure. The VISUAL ANCHOR template for each format is the starting point for the Gemini prompt's VISUAL ANCHOR block — adapt the [PLACEHOLDERS] to the specific post.

The VISUAL ANCHOR describes spatial/structural rendering — not cinematic atmosphere. The distinction: "The canvas centres on a product cross-section showing cost strata" is spatial. "Render the workflow as a corridor of vault doors glowing green" is cinematic. The first serves content. The second replaces it.

### Category B: Financial and Calculation Formats (7)

**Format 6 — Cost Anatomy**

*Format rule*: Layer width must be visually proportional to cost magnitude — the largest cost category gets the widest band. Include the % share of total for each layer.

## VISUAL ANCHOR Writing Guide

The VISUAL ANCHOR block is inserted into the Gemini prompt between THE QUESTION THIS ANSWERS and VISUAL STRUCTURE. It is 3–5 sentences. Follow these rules:

1. **Name the spatial structure first** — identify which of the 50 formats this post uses. That determines the anchor's vocabulary.
2. **Make it spatial, not atmospheric** — describe WHERE the eye goes, what DIMENSION the layout has. Not "there are 4 cards" but "the canvas reads as a geological cross-section." Not "a corridor of vault doors receding in perspective" — that is cinematic atmosphere, not layout.
3. **Name the single focal element** — the one thing the image cannot function without.
4. **Write 3–5 sentences, no more** — the VISUAL ANCHOR is a constraint device, not a scene description.
5. **No colour instructions** — the Tool Identity System handles colour. No "in blue" or "in dark".
6. **No concept explanation** — describe the visual, not what the post is about.
7. **Start from the template** — take the format's VISUAL ANCHOR template, adapt the [PLACEHOLDERS] to this post's specifics.

**The test**: could a visual designer sketch the layout from the VISUAL ANCHOR alone, without reading the rest of the prompt?

## What NOT to Do

```
NOT THIS (cinematic atmosphere replacing content):
"Render the workflow as a corridor of vault doors receding in perspective,
each door open and glowing green as the order passes through..."
→ This is deep dive register. It produces atmospheric renders, not usable tools.

NOT THIS (spatial description without real content):
"The canvas shows four elegant panels arranged symmetrically..."
→ The VISUAL ANCHOR describes the spatial logic. The content zones carry the real data.

NOT THIS (invented numbers):
"Shows: Manual time: 40 hours | AI time: 2 hours"
→ If the number isn't from a real source, remove it. Invented numbers destroy trust.

NOT THIS (wrong palette for the tool):
"A Claude post with blue and white Microsoft-style panels."
→ The tool palette is the identity. Claude = clay coral (#C15F3C) on cream (#F4F3EE).

NOT THIS (format defaulted to 4-card grid):
Assigning Sequential Steps for every post regardless of use case type.
→ Match the format to what the content IS. Use the 50-format library.

NOT THIS (annotation on every post):
Adding Tiger's opinion sentence to every single image.
→ Only when the opinion IS the point. Otherwise the image is a data tool, not an op-ed.

NOT THIS (too sparse / too dense):
Under 60 words total (looks empty, no save value) OR over 140 words (illegible at mobile).
→ The target is 80–120 words. Real content, not padding.
```
