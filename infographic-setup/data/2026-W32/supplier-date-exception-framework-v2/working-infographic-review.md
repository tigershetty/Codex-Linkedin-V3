## Craft test

- V2 was rejected: equal process cards explained the framework but did not make a causal relation
  visible.
- V3 was rejected: a visually clean route left its detailed checks detached from the thing being
  controlled.
- V4 was rejected: a richer table still read as four independent worksheet columns.
- V5 has one owned semantic object: an incoming date-change ticket first crosses the protected
  customer need-by field, then travels through credible-exposure and recovery tests; one
  conditional gate reaches the KAM + Purchasing exception. The source-derived working-object
  mechanism has been transformed into original operational cartography.
- Density is earned by actual fields, status states, the need-by marker and recovery options. It
  must not grow through smaller type, generic icons or decorative connectors.
- This is an internal test of a promise-control-card family, not a future default template. The next
  opportunity must select its own spatial relation.

## Release decision

The next valid action is a new, externally supported Resource Candidate Card followed by three
non-isomorphic visual routes; do not keep polishing or animating this test.
