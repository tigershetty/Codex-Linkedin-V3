# Tiger source — supplier-date exception framework

**Status:** internal design source for a proposed framework. It is not an external case study,
deployment claim, or public outcome claim.

## Direct operating inputs

- Customer need-by comes first.
- Unreliable supplier dates must not become false customer promises.
- Evaluate data quality and compatibility before interpreting a supplier signal.
- Test customer need-by across credible scenarios, not one asserted date.
- Make recovery options and differential economics visible.
- When any credible scenario still misses need-by after recovery, escalate as a joint KAM +
  Purchasing Manager exception decision.

## Public wording boundary

Use “a proposed operating check” or “a way to structure the decision.” Do not claim the framework
predicts delivery, reduces cost, has been deployed, or represents a universal supplier-management
standard.
