# Session Iteration Intelligence — Supplier Flexibility Matrix

**Date:** 2026-07-02  
**Purpose:** Capture what we learned from this session's render attempts so the next GPT Image 2 cycle gets better instead of merely different.

## 1. Executive Read

The strongest lesson from this session is that **we overcorrected in both directions**:

- The early GPT Image 2 matrix attempts had useful density, but looked like a generated template and failed text/status integrity.
- The HTML and Three.js controls protected exactness, but became too engineered and not emotionally competitive with top-tier reference infographics.
- The chameleon/hero tests restored visual energy, but the hero felt arbitrary: impressive, not inevitable.
- The studio-base + overlay test made the hero more relevant, but the overlay pushed it back toward pasted UI and weakened the high-end editorial feel.

**Current conclusion:**  
Do not choose a final lane yet. The next best move is not "more HTML overlay" or "more mascot hero." It is a tighter GPT Image 2 art direction that lets the image feel professionally authored while keeping the supplier-flexibility logic embedded in the scene.

## 3. What We Should Keep

1. **Scene-first rendering.** The best moments happened when GPT Image 2 created a world, not when it filled a table.
2. **One strong physical situation.** Demand spike + supplier capacity response is a real visual scene.
3. **Five supplier states.** A strong, B/C secondary, D/E risk is a clear reader payoff.
4. **Tactile logistics detail.** Mini warehouses, docks, pallets, route lines, and map-table details add credibility and save value.
5. **Cobalt/cream + one orange urgency signal.** This palette worked when orange was tied to the spike.
6. **Truth layer from HTML.** The deterministic controls give us the exact schema: suppliers, criteria, actions, verification.

## 4. What We Should Stop Doing

1. **Stop asking GPT Image 2 to render final dense text.** It creates drift, contradictions, and fake labels.
2. **Stop making the matrix the entire image.** It becomes a dashboard or worksheet.
3. **Stop using arbitrary hero metaphors.** Animal/mascot logic only works when the subject itself justifies it.
4. **Stop pasting large HTML cards over the GPT image.** That kills the high-end studio feel.
5. **Stop over-specifying UI parts in the prompt.** The model responds with generic cards, badges, callouts, and app-like panels.
6. **Stop treating "more detailed" as "more premium."** Premium here means authored hierarchy, not more objects.

## 5. The Real Design Problem

The visual should answer:

> When demand spikes, which supplier can actually absorb it, and which suppliers only look ready until you verify capacity?

That means the image needs three visible forces:

1. **Pressure:** the incoming spike.
2. **Capacity response:** how each supplier absorbs or fails under pressure.
3. **Verification:** why confidence matters before action.

If a render does not show those forces, it is decoration.

## 6. Better Creative Directions To Test

### Direction A — The Capacity Stress Table

**Visual idea:** A beautiful physical model where five supplier platforms are stress-tested by one demand spike.  
**Risk:** can become sterile if too engineered.  
**Fix:** make it editorial and cinematic, not blank-plate industrial UI.

### Direction B — The Demand Wave Breaker

**Visual idea:** A demand surge moves across a logistics map like a wave; five supplier breakwaters absorb different amounts.  
**Why promising:** clear pressure metaphor, less dashboard-like, more emotionally legible.  
**Risk:** could become too abstract if warehouses/routes disappear.

### Direction C — The Load-Bearing Supplier Bridge

**Visual idea:** Five supplier beams/platforms hold a sudden load; A holds, B/C flex, D/E crack or require inspection.  
**Why promising:** instantly explains "absorb the spike."  
**Risk:** could look like generic engineering if supply-chain details are weak.

### Direction D — The Command Table Without UI Cards

**Visual idea:** A premium logistics control-room table with five physical supplier modules, route lights, diagnostic marks, and handwritten/editorial annotations.  
**Why promising:** closest to the user's strong octopus reference without using an arbitrary hero.  
**Risk:** if over-labeled, it becomes the rejected overlay again.

## 7. Next Prompt Principle

The next GPT Image 2 prompt should **not** say:

> Create a matrix infographic with labels.

It should say:

> Create a supply-chain scene where the decision is physically visible.

Then constrain the output this way:

- no final dense text,
- no mascot,
- no UI card grid,
- no generic dashboard,
- no pasted blank label plates,
- visible five-supplier structure,
- visible pressure/capacity/verification relationship,
- leave only natural negative space for later headline and small captions.

## 8. Overlay Principle

The overlay should be **editorial annotation**, not UI.

Use:

- tiny numbered tabs,
- fine leader lines,
- small margin notes,
- restrained title/subhead/footer,
- maybe 3 to 5 labels total.

Avoid:

- large cards,
- boxed labels on every supplier,
- duplicate legends,
- thick badges,
- anything that looks like a SaaS dashboard pasted over a render.

## 9. Revised Production Path

1. **Generate visual base only:** no final text, no logos, no blank white plates. Ask GPT Image 2 for a finished editorial scene with natural annotation space.
2. **Pick based on concept relevance first:** does the hero make sense without explanation?
3. **Pick based on feed read second:** can the viewer see pressure, supplier response, and verification in two seconds?
4. **Add minimal deterministic overlay:** headline, subheading, supplier/state markers only where needed, footer/logo.
5. **Run text/data QA:** no invented claims, no status contradictions, no logo artifacts.

## 10. Hard Quality Gate For Next Render

A next candidate must pass all of these before we call it a direction:

- The hero is supply-chain-native, not decorative.
- The five supplier states are readable without labels.
- The demand spike is physically interacting with the supplier system.
- The image does not look like a template, app screen, or dashboard.
- The scene has professional restraint: fewer labels, better hierarchy, less glow.
- The overlay could be removed and the core argument would still be visible.
