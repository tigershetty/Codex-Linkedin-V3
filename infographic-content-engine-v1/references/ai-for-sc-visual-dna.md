## The Core Principle

The image is a designed document, not a designed graphic. Every element on the canvas carries real content. The visual system serves the data — not the other way around. The viewer should be able to screenshot and use the image without reading the caption.

---

## Tool Identity System (The Defining Rule)

Every AI for Supply Chain post takes on the complete visual identity of the tool it features. The image looks like it belongs to that tool — not to Shetty's Desk. The tool's palette and symbolic form are the image's brand. Shetty's Desk identity appears only in the sign-off line at the bottom.

**Critical rule on tool symbols**: Gemini cannot reproduce copyrighted logos. Do NOT ask it to "include the Claude logo" or "include the ChatGPT logo" — this produces generic placeholders. Instead, describe the geometric form of the symbol precisely. Gemini renders described shapes accurately. The colour + geometric form together produce instant brand recognition without copying a trademark.

### Tool Identity Reference

**CLAUDE (Anthropic)**
- Background: Warm off-white (#FAF8F5) or deep charcoal (#1A1A1A)
- Accent: Anthropic coral (#E8612A)
- Symbol — describe exactly as: "An 8-pointed starburst with slightly curved, tapering arms radiating from a small hollow centre point — like a snowflake with smooth organic arms, not sharp geometric points. Rendered in Anthropic coral. Large, structural — a centrepiece or prominent panel element, not a corner watermark."
- Feel: Warm, intelligent, document-grade. The Asmaa Gad "Layers of Claude" and "Claude Code for Supply Chain" posts in the reference set nail this aesthetic.

**CHATGPT (OpenAI)**
- Background: Near-black (#0D0D0D) or dark charcoal (#1E1E1E)
- Accent: OpenAI green (#10A37F)
- Symbol — describe exactly as: "A smooth, continuous loop forming a stylised rounded shape — two curved forms completing each other in a fluid, seamless circle, like an infinity symbol closed into itself. Rendered in OpenAI green on dark background."
- Feel: Dark, premium, technical authority.

**COPILOT (Microsoft)**
- Background: White (#FFFFFF) or light grey (#F5F5F5)
- Accent: Microsoft blue (#0078D4)
- Symbol — describe exactly as: "A swirling multi-section circle divided into 4 colour-coded arc segments — blue, green, yellow, red — arranged like a pinwheel or stylised colour wheel, the segments slightly separated with white gaps between them. Microsoft brand colours."

**GEMINI (Google)**
- Background: White (#FFFFFF) or very light grey
- Accent: Rotating use of Google blue (#4285F4), red (#EA4335), yellow (#FBBC05), green (#34A853)

- Accent: White panels, each tool's accent colour used inside its comparison column
- Symbols: Each tool's geometric symbol rendered small and equal size, one per column header
- Feel: Neutral referee — no tool is favoured visually.

## The Four Visual Structures

Only use these four. They are the only structures that perform across the reference set. Choose based on what the content IS — not on what looks interesting.

### Structure 1 — Numbered Row Cards
**Content type**: Sequential steps, ranked items, numbered principles, ordered workflow.
**When to use**: The content has a clear order and each item is roughly equal weight.
**Layout**: N cards in a grid (2×3, 2×4, 1×5) or vertical stack. Each card = number (large, in accent circle) + bold item title + 2–3 line description.
**Hero element**: The number in each circle. The largest numbers are 3–4× the size of body text.
**Examples from reference set**: "6 Procurement AI Principles", "5 Surprising Truths about Agentic AI", "8 AI Models Ranked"

### Structure 2 — Comparison Matrix / Table
**Content type**: Two or more things compared across consistent dimensions. Tool vs tool, approach vs approach, before vs after.
**When to use**: The point IS the comparison. The viewer needs to scan across rows.
**Layout**: Rows = items being compared. Columns = dimensions. Header row in accent colour. First column bold (item names). Cells contain 3–6 word labels, not sentences.
**Hero element**: The one cell that tells the whole story — the most important comparison point, colour-highlighted.
**Examples from reference set**: "Supply Chain vs Logistics vs Shipping", "AI Exposure Index" (roles × AI exposure %), "8 AI Models Ranked" matrix

### Structure 3 — Stepped Hierarchy / Pyramid
**Content type**: Levels that build on each other. Maturity model, capability ladder, depth progression.
**When to use**: The content is genuinely hierarchical — lower levels enable upper levels.
**Layout**: Trapezoid layers stacked vertically, widest at bottom. Each layer = level name + 2–3 bullet capabilities. Progression arrow or label on the side.
**Hero element**: The top level — smallest area, most premium feel, the destination.
**Examples from reference set**: "Layers of Claude for Procurement", "3 Levels of AI"

### Structure 4 — Process Flow
**Content type**: A sequence where order matters and each step hands off to the next.
**When to use**: You are showing HOW something works from start to finish.
**Layout**: Left-to-right or top-to-bottom flow. Each step = a node (box or circle) + step name + one-line description. Connector arrows between nodes. Optional: owner role beneath each node.
**Hero element**: The step where things break or where the most value is created — visually distinct from the others (different colour, border, or label).
**Examples from reference set**: P2P flow (vault doors post), "How to Shift Procurement from Tactical to Strategic"

## The Hero Number

Every post has one number that is the reason to save the image. It is 3–4× larger than all surrounding text. It is real and specific — never an estimate, never "X%".

**For AI for SC posts, the hero number is the time comparison:**
- Format: "[Manual time] → [AI-assisted time]"
- Example: "3 days → 20 min" for an RFQ post
- Source: Field benchmarks — industry-reported task durations for manual vs. AI-assisted work
- Placement: Prominent on the image, near the top or as the opening element of the first card

**Finding a credible benchmark**: If the post is about a real SC task (RFQ writing, safety stock calculation, supplier scorecard), there is always a documented industry benchmark for manual time. Use it. If it cannot be sourced, use a conservative estimate and frame it as "typically" — but never invent a specific figure.

## Typography Rules

| Element | Style |
|---|---|
| Post heading | Bold, large, 5–8 words maximum. One word or phrase in accent colour (not the whole heading). |
| Section / card labels | ALL CAPS or Title Case Bold. 2–4 words. White on dark or accent-colour on white. |
| Body text per card | Regular weight. 15–25 words maximum. Never a full paragraph. |
| Hero number | Bold, 3–4× larger than body. In accent colour or white. Stands alone — not inside a sentence. |
| Annotation line (optional) | Italic or smaller regular weight. One sentence. Set apart from the grid at the bottom. Only when the opinion IS the point of the post. |
| Sign-off | Small, bottom of image. "Shetty's Desk · Poornajith Shetty" |

**Maximum 2 font families.** Bold sans-serif for headings and numbers. Regular weight of same family for body. No mixing serif and sans-serif.

---

## Content Density Rules

Total text on image (all labels, all cards, heading, annotation): **80–120 words**.

This is more than the previous 60-word rule. The reference images that work carry real content — they are not sparse. But every word is earned. No filler phrases, no "Learn more about...", no decorative labels.

Per card: maximum 25 words of body text. Card label does not count toward word budget.

**Every number on the image must be real.** If you cannot source a real number, do not put a number there. Remove the data point rather than invent it.

---

## The Annotation Line

**Only used when**: The post's core value is a perspective or reframe — not just information. Leader posts more often than Practitioner posts.

**Format**: One sentence. Below the main grid. Smaller than body text. Not bold. Not in a panel — floating, set apart.

**What it is not**: A summary of what the image shows. A caption repeat. A call to action.

**What it is**: Tiger's one-sentence editorial position on the topic. The thing that could not fit in a table.

Examples of the right register:
- "AI writes the document. You own the decision."
- "The gap isn't the tool. It's the 20 minutes nobody builds into the process."
- "Data doesn't make the call. You do."

## Gemini Prompt Structure for AI for SC Posts

Use this structure every time. No creative metaphors. No cinematic atmosphere. The prompt specifies content in containers.

```
Task: Create an infographic image for the summary below (after the rules).

Rules: Use the image attached as a reference on style, aesthetics, colours, and illustration technique. Use a different layout for the structure to elaborate details based on the summary. Do not use any information or text from the attached image — only style. Use it only for inspiration. Aspect ratio 1:1, resolution 2048x2048.

TOOL IDENTITY: [Tool name] — use [Tool]'s complete visual palette. Background: [colour]. Accent: [colour hex]. Tool symbol: render [exact geometric description from Tool Identity Reference — copy verbatim]. Position the symbol [top-right / centred / as described]. This image should look like it belongs to [Tool]'s brand without reproducing any trademarked logo.

TOPIC: [Topic name]
THE QUESTION THIS ANSWERS: [The real task the viewer faces]

VISUAL STRUCTURE: [Structure 1/2/3/4 from above]. [One sentence on the specific layout — e.g. "Six numbered cards in a 2×3 grid, each card with a large number circle in the top-left, bold title, and 2-line description."]

HERO NUMBER: "[X time] → [Y time]" — this is the largest text element on the image, positioned [top-centre / inside card 1 / above the grid].

CONTENT TO INCLUDE ON THE IMAGE:
- Heading: "[5–8 words]" (Bold — one key phrase in accent colour)
- Tool symbol: [geometric description from Tool Identity Reference] — positioned [top-right / top-left / centred], large and structural, not a corner watermark
- [CARD/ROW/STEP 1 LABEL]: [15–20 word description]
- [CARD/ROW/STEP 2 LABEL]: [15–20 word description]
- [CARD/ROW/STEP 3 LABEL]: [15–20 word description]
- [CARD/ROW/STEP 4 LABEL]: [15–20 word description — add more as needed]
- [ANNOTATION LINE — optional, only if opinion is the point]: "[One sentence, Tiger's position]"
- Sign-off line (small, bottom): "Shetty's Desk · Poornajith Shetty"

CONTENT RULES:
- Total words on image: 80–120 (all text combined)
- Hero number is 3–4× larger than body text — it is the first thing the eye finds
- Every number is real — no placeholder figures
- Maximum 2 font families throughout
- Every element readable at mobile phone size (minimum 14px at 2048px output)
- All content inside defined containers (cards, panels, cells) — no floating labels
- [Tool logo/icon] is a visual element, not a watermark

DO NOT:
- Use font sizes below 14px at final output resolution
- Add decorative elements that do not carry information
- Use gradients on backgrounds — solid colour panels only
- Place text on complex or illustrative backgrounds
- Use more than 2 font families
```

## What NOT to Do

```
NOT THIS (visual metaphor replacing content):
"Render the workflow as a corridor of vault doors receding in perspective,
each door open and glowing green as the order passes through..."
→ This is deep dive register. It produces atmospheric renders, not usable tools.

NOT THIS (invented numbers):
"Shows: Manual time: 40 hours | AI time: 2 hours"
→ If the number isn't from a real source, remove it. Invented numbers destroy trust.

NOT THIS (wrong palette for the tool):
A Claude post with blue and white Microsoft-style panels.
→ The tool palette is the identity. Claude = Anthropic coral on warm off-white.

NOT THIS (annotation on every post):
Adding Tiger's opinion sentence to every single image.
→ Only when the opinion IS the point. Otherwise the image is a data tool, not an op-ed.

NOT THIS (too sparse / too dense):
Under 60 words total (looks empty, no save value) OR over 140 words (illegible at mobile).
→ The target is 80–120 words. Real content, not padding.
```
